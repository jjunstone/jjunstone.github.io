AI DevOps Control Center

Kubernetes 기반 CI/CD 운영 환경을 AI Agent가 관찰·분석하고, 정책 검증과 사람의 승인을 거쳐 제한된 운영 작업을 수행하도록 설계하는 학습형 프로젝트입니다. 인프라·보안 운영 경험을 Cloud Platform Engineering / DevOps 역량으로 확장하기 위해 직접 구축하며 학습하고 있습니다.

왜 이 프로젝트인가

지금까지의 경력은 Windows Server·Active Directory·방화벽·보안 운영 등 엔터프라이즈 인프라 운영을 중심으로 쌓아왔습니다. Azure/M365 기반 자동화와 사내 AI·RAG 플랫폼 구축까지 경험했지만, Kubernetes·CI/CD·Container 같은 클라우드 네이티브 운영 경험은 상대적으로 부족했습니다.

동시에 AI를 다루는 방식에도 고민이 있었습니다. LLM을 단순히 호출해 요약하거나 코드를 작성하는 수준(Prompt Usage)과 사내 RAG를 구성하는 수준(Context Engineering)을 넘어, 실제 운영 프로세스 안에서 AI가 판단하고 도구를 호출하는 Agent / Harness Engineering까지 이해하고 싶었습니다.

기술 갭 해소Kubernetes / Docker / CI/CD / Observability를 직접 구축하며 클라우드 네이티브 운영 구조를 체득
AI 역량의 증명"AI를 붙였다"는 인상이 아니라 운영 시스템에 AI가 들어갈 올바른 위치를 설계했다는 근거를 남김
커리어 방향 전환보안 운영 중심 경력을 Cloud Platform / DevOps / Automation 역량으로 확장하는 다리 역할
안전한 자동화 설계반복 작업은 자동화하고, 판단이 필요한 부분에 AI를, 위험한 변경에는 사람 승인을 두는 구조를 실제로 구현

설계 원칙

1AI에게 모든 것을 맡기지 않는다.
2결정론적인 작업은 일반 자동화로 처리한다.
3판단·해석이 필요한 부분에만 Agent를 사용한다.
4Agent의 Tool과 권한을 명시적으로 설계한다.
5위험한 변경에는 Policy와 Human Approval을 둔다.
6실행 결과를 반드시 다시 검증한다.
7모든 행동은 Audit Log로 남긴다.

“인프라 운영의 구조를 이해하고, 반복 가능한 작업은 자동화하며,
판단이 필요한 곳에는 AI를 올바른 위치에 둔다.”
