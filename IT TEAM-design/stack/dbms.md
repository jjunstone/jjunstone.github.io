# 데이터베이스 관리 시스템 (DBMS)

## 용도
- 금융 거래 데이터 저장
- 고객 정보 관리
- 원장 및 거래 기록
- 고가용성 요구 (99.9% SLA)
- 개인정보 암호화 (개인정보보호법 제30조)

## 이 기술 때문에 생기는 업무

### 정기 업무
- 일일: 백업 검증, 성능 모니터링
- 주간: 성능 분석, 인덱스 최적화
- 월간: 보안 패치 적용, 용량 계획

### 요청 기반 업무
- 신규 데이터베이스 생성
- 스키마 변경
- 접근 권한 부여

### 장애 업무
- 데이터베이스 복구
- 복제 동기화 오류 해결
- 성능 저하 대응

## 연결되는 다른 기술
- 백업 솔루션 (S7)
- 암호화 솔루션 (S8)
- 모니터링 플랫폼 (S5)
- 클라우드 인프라 (S6)
- Kubernetes (컨테이너 환경에서 실행 시)

## 담당과 승인 경계
- 담당: DBA팀장, DB사원
- 승인: DBA팀장 (최종)
- 협력: 보안팀장 (암호화), 인프라관리사원 (백업)

## 관련 규제 조항
- 개인정보보호법 제30조: 암호화, 백업
- ISO 27001 A.12.4: 백업 및 복구
- ISMS-P: 데이터 백업 및 보안
- 전자금융거래법: 거래 기록 보관

## 10명으로 운영 가능한 이유 또는 한계
**가능한 이유:**
- 관리형 클라우드 서비스 (Azure) 활용으로 운영 부담 감소
- 자동화된 백업 및 복구
- 자동 패치 관리

**한계:**
- 고급 성능 튜닝에는 전문가 필요
- 대규모 데이터 마이그레이션은 외부 지원 필요

## 대안 비교

### 옵션 A: Oracle Database Enterprise Edition
**개요:** 상용 DBMS, 최고 성능
**장점:** 강력한 HA (RAC), 금융권 표준, 풍부한 기능
**단점:** 높은 라이선스 비용, 복잡한 관리, 잠금 위험
**10명 운영 적합도:** 낮음 (전문가 필수)
**규모감:** 고 (많은 리소스)
**규제 적합성:** 완전 준수
**회수비용:** 매우 높음 (라이선스 종료 시)
**다른 영역 영향:** 높은 운영 비용 → 다른 투자 제약

### 옵션 B: PostgreSQL (Azure Managed Database)
**개요:** 오픈소스, 관리형 서비스
**장점:** 낮은 비용, 충분한 HA, 관리 간단, 금융권 도입 증가
**단점:** 금융 전문 커뮤니티 작음
**10명 운영 적합도:** 높음 (자동화 우수)
**규모감:** 중 (적절한 리소스)
**규제 적합성:** 완전 준수
**회수비용:** 중간 (클라우드 → 온프레미스 마이그레이션 가능)
**다른 영역 영향:** 낮은 비용 → 다른 기술 투자 가능

### 옵션 C: SQL Server (Azure Managed)
**개요:** 마이크로소프트 엔터프라이즈 DBMS
**장점:** Windows 통합, HA 기능 우수, 좋은 도구
**단점:** 중간 수준의 라이선스 비용
**10명 운영 적합도:** 중-높음
**규모감:** 고
**규제 적합성:** 완전 준수
**회수비용:** 중-높음
**다른 영역 영향:** 중간 (Azure 생태 깊음)

## 권장안 및 근거
**권장: PostgreSQL (Azure Managed Database)**

**근거:**
1. 비용 효율성: 라이선스 비용 최소화
2. 운영 효율성: 자동화 수준 높음 (10명 팀 최적)
3. 규정 준수: 모든 금융 규정 충분히 만족
4. 유연성: 클라우드 ↔ 온프레미스 전환 가능
5. 커뮤니티: 금융권 도입 확대로 지원 개선

절감된 예산: Oracle 대비 연간 40-50% 절감
→ 보안, 모니터링, DevOps 인프라에 투자 가능
