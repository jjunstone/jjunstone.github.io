# 보안 패치 관리 흐름

## 트리거
보안 공지 또는 정기 패치 리리스

## 단계별 담당 역할

1. 보안팀장: 패치 가용성 확인
2. 보안팀장: 위험도 평가 (Critical/High/Medium/Low)
3. Critical: 72시간 이내 적용
4. High: 2주 이내 적용
5. 서버과장: 테스트 환경에서 패치 테스트
6. 보안팀장: 배포 승인
7. 서버과장: 정기 유지보수 시간 예약
8. 서버사원: 프로덕션 패치 적용
9. 서버과장: 기능 검증
10. 패치 기록 (감시 시스템)

## 각 단계의 승인·검증·기록

| 단계 | 승인 | 검증 | 감시로그 |
|------|------|------|---------|
| 2 | - | 공개된 취약점 심각도 | 평가 기록 |
| 5 | - | 테스트 환경 기능 동작 | 테스트 결과 |
| 6 | 보안팀장 | 위험도 및 기한 확인 | 승인 타임스탐프 |
| 8 | 서버과장 | 프로덕션 적용 확인 | 패치 적용 시간 |
| 9 | 서버과장 | 서비스 정상 동작 | 검증 기록 |

## 실패 시 처리
- 테스트 환경에서 실패: 수정 후 재테스트
- 프로덕션 배포 실패: 롤백 (복구 절차 실행)
- 알려지지 않은 부작용: 긴급 롤백, 근본 원인 분석

## 남는 감사 증적
- 패치 ID 및 심각도 평가
- 테스트 결과
- 배포 승인 기록
- 적용 시간 및 시스템
- 롤백 기록 (발생 시)

## 자동화 가능 지점
- 패치 감지 자동화 (취약점 데이터베이스 모니터링)
- 테스트 환경 자동 배포
- 프로덕션 배포 자동화 (승인 후)
- 롤백 자동화 (실패 감지 시)
- 패치 상태 리포트 자동화
