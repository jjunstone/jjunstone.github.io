# CI/CD 배포 흐름 (클라우드-네이티브)

## 트리거
개발팀의 코드 커밋 또는 수동 배포 요청

## 단계별 담당 역할

1. 개발자: 코드를 Git에 커밋
2. CI/CD 파이프라인: 자동 트리거
3. DevOps사원: 자동 테스트 및 보안 스캔 모니터링
4. 보안팀장: 취약점 스캔 결과 검토
5. DevOps사원: 컨테이너 이미지 빌드 및 레지스트리 푸시
6. 인프라/DevOps과장: 배포 정책 및 요구사항 확인
7. DevOps사원: Kubernetes에 자동 배포 (rolling update)
8. 모니터링: 배포 후 애플리케이션 헬스 확인
9. 배포 로그 기록 (감시 시스템)

## 각 단계의 승인·검증·기록

| 단계 | 승인 | 검증 | 감시로그 |
|------|------|------|---------|
| 3 | - | 자동 테스트 통과 | 테스트 결과 |
| 4 | 보안팀장 | 취약점 수용 가능 수준 | 스캔 결과 타임스탐프 |
| 6 | 인프라/DevOps과장 | 정책 준수 확인 | 승인 기록 |
| 7 | - | Pod 정상 기동 확인 | 배포 시간, 버전 |
| 8 | - | 애플리케이션 응답 확인 | 배포 후 헬스 체크 |

## 실패 시 처리
- 보안 스캔 실패: 개발팀이 취약점 수정 후 재커밋
- 배포 실패: 자동 롤백 (이전 버전으로 복구)
- 헬스 체크 실패: DevOps과장이 원인 파악, 롤백 또는 수정

## 남는 감사 증적
- Git 커밋 로그 (코드 버전)
- CI/CD 파이프라인 실행 로그
- 보안 스캔 결과 및 승인 기록
- 배포 시간 및 버전
- 롤백 기록 (발생 시)

## 자동화 가능 지점
- Git 커밋 → 자동 파이프라인 트리거
- 자동 테스트 (단위, 통합, 부하)
- 자동 보안 스캔 (SAST, 컨테이너 이미지)
- 자동 배포 (승인 후)
- 자동 롤백 (헬스 체크 실패 시)
