# 인프라/DevOps 과장 역할

## 책임 범위
- Kubernetes 클러스터 운영 및 최적화
- CI/CD 파이프라인 구축 및 관리
- 컨테이너 보안 및 컴플라이언스
- 개발팀과 인프라팀 협력 조정

## 일일 보는 지표 및 화면
- Kubernetes 클러스터 상태 대시보드 (노드, Pod, 리소스)
- 배포 파이프라인 성공률
- 컨테이너 이미지 취약점 스캔 결과
- 애플리케이션 성능 메트릭 (응답시간, 에러율)
- 비용 최적화 지표 (리소스 사용률, 클라우드 비용)

## 주간 정기 업무
- Kubernetes 클러스터 성능 분석 및 튜닝
- 배포된 애플리케이션 모니터링 리포트 작성
- 보안 패치 계획 (OS, 라이브러리, 컨테이너 이미지)
- 인프라 용량 계획 및 확장 검토
- 개발팀과 배포 자동화 협력 회의

## 월간 정기 업무
- 클러스터 백업 및 복구 테스트
- 보안 취약점 스캔 및 개선 계획
- 비용 최적화 검토 (리소스 사이징, 예약 인스턴스)
- CI/CD 파이프라인 성능 최적화
- ISMS-P, ISO 27001 컴플라이언스 검증

## 같은 사건을 보는 관점

### 배포 실패 시나리오
- **인프라/DevOps과장**: 자동 롤백 기능, 배포 속도 복구, 클러스터 안정성 확보
- **서버과장**: 하드웨어 리소스 확인, 인프라 용량 문제 여부
- **보안팀장**: 배포에 포함된 코드 보안성, 취약점 스캔 결과
- **DBA팀장**: 데이터베이스 마이그레이션 영향, 거래 안전성

### 컨테이너 보안 위협 감지 시나리오
- **인프라/DevOps과장**: 악의적 Pod 격리, 이미지 업데이트, 네트워크 정책 강화
- **보안팀장**: 침투 원인 분석, 애플리케이션 코드 검증, 규정 위반 여부
- **네트워크과장**: 네트워크 트래픽 차단, 방화벽 규칙 강화

### 성능 저하 시나리오
- **인프라/DevOps과장**: Pod 재배포, 노드 추가, 리소스 할당 조정
- **서버과장**: 클러스터 노드 하드웨어 상태 확인
- **개발팀**: 애플리케이션 코드 최적화 필요 여부 검토

## 가장 자주 협업하는 역할
1. DevOps사원 (일일)
2. 개발팀 리더 (2-3회/주)
3. 서버과장 (2회/주)
4. 보안팀장 (1-2회/주)
5. DBA팀장 (배포 시 조율)

## 장애 시 첫 행동
1. Kubernetes 클러스터 상태 확인 (노드, 네트워크, 스토리지)
2. 배포 파이프라인 로그 검토
3. 영향받은 Pod와 서비스 격리 판단
4. 자동 복구 시도 (Pod 재시작, 노드 재부팅)
5. 실패 시 즉시 DevOps사원 + 서버과장 호출
6. 심각도에 따라 DBA팀장에 에스컬레이션

## 요구 기술 스택
- Kubernetes (Azure Kubernetes Service / AKS 권장)
- Docker 컨테이너 기술
- GitLab CI/CD 또는 Azure DevOps Pipeline
- Helm 차트 관리
- 모니터링 도구 (Prometheus, Grafana, Azure Monitor)
- Infrastructure as Code (Terraform, Helm)
